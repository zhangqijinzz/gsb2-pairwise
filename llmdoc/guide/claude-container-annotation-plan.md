日期：2026-09-12。

状态：已实施，新增“容器标注”入口；使用方法见 [操作指南](claude-container-annotation.md)。已完成临时材料与模拟审核器的流程验证，真实付费审核和项目方验收不属于此次代码验证。

## 1. 目标与范围

在现有 PinRu 上接入用户自行启动、自行交互的 Claude Code Docker 会话，自动关联题目、采集轨迹与轮末产物、调用 coding-agent-satisfaction 审核并持久保存。所有题目完成后，以项目批次统一预检、统一导出一份 28 列 Excel 及配套材料。

“数据质量达标”要求真实、完整、可追溯且符合字段及评分规范。它不要求模型全部获得 5 分，不允许删掉低分轮次、润色原始 Prompt、编造验证或把 AI 评价写成人工评价。项目方最终接收独立于程序内部检查；现有 skill 引用的原始规范含禁止 AI 标注条款，因此本方案不能承诺符合该条款或保证外部接收，应保留 AI 评价来源和接收口径未确认状态。

用户继续负责容器启动及被测 CLI 输入。PinRu 不自动追加被测对话，不把建议提示词当成已经发生的轮次。采集与审核可逐轮进行，正式 Excel 在整批完成后统一导出。

## 3. 用户操作与状态

操作顺序：导入项目并生成题目 → 各题准备初始提交 → 用户启动新容器 → 绑定题目并导入仓库 → 用户输入 Prompt → 本轮完成后采集并审核 → 按需继续修复 → 整批预检 → 统一导出。

任务界面保留当前看板结构，新增或调整以下入口：

| 入口 | 行为与反馈 |
| --- | --- |
| 绑定容器 / 准备题目 | 选择实际容器，显示真实代码目录，复制仓库并核对初始状态；已存在目标不得覆盖 |
| 采集并审核 | 固定轨迹与本轮产物状态，分析有效轮次，显示五维评分、依据和证据缺项 |
| 下一轮建议 | 可查看、编辑、复制；只有轨迹中真实出现后才成为轮次 |
| 完成本题 | 结束本题工作登记；允许低分结束，不要求五项满分，不自动停止或删除容器 |
| 批次预检 | 展示已登记题数、真实有效轮数、未审核轮数、待补证据和阻断问题 |
| 导出本批 | 使用同一份冻结的记录清单生成 Excel、原始轨迹附件、证据索引及检查报告 |

题目执行状态、材料是否完整、评价是否完成、导出检查状态和外部审核状态分别保存。内部检查通过不能写成项目方“审核通过”。

## 4. 从旧审核规范提取的规则

以本批五维规范和 skill 的证据规则为准，旧审核经验仅作实施方法补充，不能引入新的评分门槛。

| 旧规则或做法 | 调整决定 |
| --- | --- |
| 只依据读取过的代码、真实 Prompt 与可定位证据 | 保留；补充轨迹中的执行者归属、本轮结束状态及独立复验范围 |
| 核对入口、数据变化、持久化、界面反馈 | 保留，按实际任务选择相关环节，不对每题强制全套业务检查 |
| 修复核对原触发条件及相邻边界 | 保留；结果需注明来自原轨迹、独立复现还是静态判断 |
| 过程问题与产物问题分开 | 保留并展开为五维，不能从一个产物缺陷自动推导另外四项扣分 |
| 修复提示词聚焦当前真实问题，少用复审术语 | 保留；必要的命令、文件或接口定位可写，不能为口语化损失准确性 |
| 约 90 分才满意、80% 只能完成 | 不带入；五维分别依据正式 1—5 锚点评分，不换算总分 |
| 证据不足填 false，描述仅写“异常输出” | 不带入；保存具体缺项，相关维度可待补，已有可靠评分正常完成 |
| 固定“过程不满意：…产物不满意：…”两段 | 不带入；五个描述栏分别写自然语言，内容按维度对应 |
| 没有 TODO、验收矩阵或固定计划格式就扣分 | 不带入；只有实际拆解、进度追踪、歧义处理问题才能支持规划扣分 |
| 仅承认 Prompt 显式写出的约束 | 调整；也考虑必要正确性、兼容性和业务目标可推导的约束，并写出推导依据，不能自行追加需求 |
| 不满意就必须给 Bug 修复词 | 调整；区分未解决缺陷、仅过程不足、证据缺失；不为低分虚构 Bug |
| 强制“修复”开头、正则截成三句、删除代码词 | 不作为质量标准；先保留事实和必要条件，再自然改写，最后核对语义 |
| 样表已通过就照分数和理由仿写 | 不采用；样表提供格式参考，评分仍须回到当轮证据 |

样表中“没有先列出验收矩阵”的表述本身不能证明规划不足；“测试只留在临时目录”也不自动成立扣分，需要结合本题要求、实际验证及可复验影响。本文不据此直接改动样表分数。

### 5.2 结构化评价记录

每轮至少包含：任务绑定、真实 SessionID、PromptID、原始 Prompt、事件顺序与边界、有效性及排除原因、初始快照、本轮产物指纹、实际执行环境、题型与难度、五项整数分数及各自描述、证据引用、缺项、真实问题列表、下一轮建议类型与内容。

评价版本包含技能及参考文件指纹、评价模型信息、生成时间、证据包版本和替代的旧评价版本。运行失败不能覆盖已经有效保存的结果。

评分由 AI 完成；程序负责校验和保存，不能根据文字猜分数。缺证据的维度以空值和明确缺项保存，不用 0、3 或 5 代填。

### 5.3 自然语言处理

流程：完成事实与评分 → 按维度写依据 → 去掉空话和机械格式 → 逐格检查事实、严重程度、分数及验证归属是否变化。机械词语替换只作提醒，不作通过标准。

保留必要文件名、函数或操作场景；大量日志行号和命令移入证据索引。禁止补写“我亲自试了”等不存在的体验。自然语言是为了易读，不能用于隐藏 AI 来源。

### 5.4 下一轮建议

暂以“任意一项低于 5 分时检查是否需要后续建议”作为待确认默认；此前歧义询问尚未得到明确回答。触发条件不改变评分，也不直接强制产生 Bug。

- 有已证实、尚未修复的问题：生成简短提示词，写清实际场景、当前异常和预期结果；多项问题保留各自证据，避免拼接无关功能。
- 只存在过程效率或规划不足：保留评价，若没有可行动的后续问题，说明无必要修复，不制造产品缺陷。
- 只有材料缺失：先补证据，不让被测模型“修复”评价助手缺少的信息。
- 最多 10 个有效轮次；达到上限停止追加引导。历史已超限照实记录，不删轮或换会话规避。

## 6. 仓库、轮次与缓存设计

### 6.1 首轮前准备

各题源代码副本准备完成后确保存在真实提交，持久记录完整 SHA。已有 Git 目录也要检查 HEAD 是否有效，不能仅凭 `.git` 存在判断初始化完成。准备失败不能显示可开始。

容器等待输入时复制题目仓库，必须保留对应提交对象并核对文件状态；不能调用会重新创建快照提交的通用复制方法而悄悄更换 SHA。复制模式创建新的目标目录，拒绝覆盖正在作答的目录。依赖准备若改变跟踪文件，必须在首轮前更新基线并记录，或回到明确的基线状态。

远端链接与本地 SHA 分开保存。已有发布能力仅可在本会话授权范围内复用；正式材料检查需确认对应 commit 可访问，不能仅检查 URL 长相。不把执行后的新提交冒充首轮前快照。

### 6.2 原始材料与轮次

容器绑定保存容器 ID、显示名称、挂载路径、仓库相对位置和轨迹来源。同名容器重建后重新绑定。SessionID 和项目关系由真实记录、仓库路径及当前绑定交叉核对，多候选时不得选最新文件冒充目标。

按实际日志 schema 识别用户输入、工具返回、重试、压缩、子代理及结束事件。重复 PromptID 需核对事件链及重复原因，冲突内容保留待查，不能仅按文本或 UUID 去重。待完成或工程故障轮次单独记录，不能自动算成功或模型失败。

每轮在模型等待输入时采集，检查采集前后轨迹及相关代码是否变化；不稳定则重试或报待采集。保留原始目录结构、必要子代理轨迹及附件。数据库只存索引，大文件留在证据目录。

历史任务若只有最终代码，不能保证恢复每轮状态；结合可信快照及轨迹还原，无法可靠还原的维度明确待补。

### 6.3 持久化与幂等

SQLite 保存任务绑定、会话、真实轮次、独立评价版本和批次导出记录。轮次主身份使用 SessionID + PromptID，评价重试与版本更新不增加轮次数。

缓存依据相关轨迹内容、轮末产物、初始快照、技能规则和评价配置判断有效性。只有后续事件追加且早期证据未变化时可以复用早期评价；发现早期证据或规则变化时标记需要复核，保留旧版本。

独立验证使用副本并记录代码状态、命令、退出状态及输出。不要静默修复被测代码，也不要把评价助手产生的测试记成模型已完成的测试。

## 7. 所有题目完成后统一导出

默认批次对应当前选定项目中的本批题目。导出前列出范围并生成清单；所有已登记题目必须有完成状态或明确的缺项处理，不能因查询失败而被当成零轮次忽略。

统一导出流程：

1. 从原始轨迹清单对账所有题目与有效轮次，保留被排除轮次及有证据的原因。
2. 检查所有有效轮次已有适用的评价版本，缺证据和缺字段定位到题目、轮次和字段。
3. 对评分锚点、证据归属、描述与分数的一致性做语义复核；已有可靠结果直接复用，仅复核变化或有问题的记录。
4. 冻结本次导出的题目范围、轨迹及评价版本；导出期间新增轮次或重新评分不混入当前文件，下次导出采用新版本。
5. 按原 28 列模板输出一份 Excel，按题目稳定排序，同一会话按真实事件顺序排列，每有效轮次一行。
6. 同批复制原始轨迹附件，生成轮次清单、证据索引和检查报告；相对路径在完整交付目录中可解析。
7. 重新打开 Excel，核对 Prompt 原文、ID、分数类型、列序、枚举、附件以及下拉范围；运行技能只读检查器。
8. 保存导出版本与内容指纹。相同版本重复导出内容对应相同记录，不重复添加数据行。

不能按 consumeQuota、旧满意度、模型分数或“最后一轮成功”筛除记录。失败但有效的轮次照常导出。规范风险与模型表现分开标记，不能让低分自动变成无效数据。

有阻断缺项时不标“检查通过”；仍允许导出完整范围的待补材料包，明确哪些单元格为空及原因，不静默只导出好填的行。字段错误或描述污染由系统修正后重检；事实缺失不能自动补造。外部审核字段和提交时间按真实流程保存，不拿文件生成时间冒充提交时间。

## 9. 最低验收场景

- 一题一轮、两题多轮、前轮失败末轮成功：每个有效轮次恰好一行，早期评分不受最终代码影响。
- user 工具结果、子代理事件、重复事件、压缩摘要、同文本的不同输入：轮次身份与实际链路一致。
- 同 PromptID 不同内容、缺 PromptID、未完成响应：保留冲突或缺项，不随机生成 ID。
- 工程故障中断与真实模型缺陷共存：分别归因，不整轮机械低分或删除。
- 五项高低混合、全满分、只有过程不足、某一维缺证据：评分、后续建议和材料状态分别正确。
- 初始 SHA 缺失或与执行仓库不一致：不能冒充已有初始快照；远端未核查不能显示可访问。
- 导出前新增轮次、审核失败、重复点击、程序重启：不遗漏、不重复、不混合评价版本。
